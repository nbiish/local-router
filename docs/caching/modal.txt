Modal (inference gateway / Shared Endpoints) — Prompt/Context Caching
Last verified: 2026-11-20

Overview
  Modal serves OpenAI-compatible LLM inference two ways:
  - Shared Endpoints: Modal-managed capacity for supported base models,
    billed per token.
  - Dedicated Endpoints: your own containers (including custom weights),
    billed per GPU-second, with configurable routing/compute regions.
  Both are reached through the inference gateway:
  https://inference.us-west.modal.direct/v1
  The `modal` provider row points here. The previous host,
  https://api.us-west-2.modal.direct/v1, answers `404 route not found`
  (measured 2026-11-20) and no longer describes any live surface.

Authentication (unresolved for this row)
  Modal distinguishes two credential families:
  - API tokens (`ak-` / `as-`), workspace-level.
  - Proxy tokens (`wk-` / `ws-`), which are what Endpoints authenticate with.
  The `modal` row is declared as an `ak-`/`as-` API-token provider
  (`MODAL_API_KEY`), but a `wk-`/`ws-` proxy pair is what was available to
  probe with, and it is rejected:
      GET /v1/models -> 401 {"error":"invalid proxy auth credentials"}
  No `ak-`/`as-` token is in the vault, so the served catalog for this row is
  UNVERIFIED as of 2026-11-20. The registry rows keep their prior model ids
  with explicit "unverified" notes rather than silently claiming them.
  Own-deployment work belongs on the `modal-proxy` row, which already
  implements proxy-token auth (see docs/caching/modal-proxy.txt).

Mechanism
  Automatic prefix caching (vLLM APC) on Shared Endpoints. vLLM caches KV
  blocks of prior queries and reuses them when a new request shares a
  token-identical prefix (PagedAttention block granularity, typically
  16-token blocks). There is NO explicit cache_control / breakpoint API, no
  cache IDs, and no TTL knobs — prefix reuse is implicit and per serving
  replica. Dedicated Endpoints are your own server, so caching follows
  whatever engine you deployed.

Max configuration
  Nothing to configure client-side on Shared Endpoints: send stable,
  identical prompt prefixes and APC applies automatically while the same
  replica stays warm. Server-side the deployer pins
  `enable_prefix_caching=True` (vLLM default) and can extend KV offload
  tiers; clients cannot influence this.

Limits & thresholds
  - KV cache lives in replica GPU/CPU memory only; it is evicted under memory
    pressure via LRU and disappears entirely on scale-down / cold start.
  - Shared Endpoints scale to zero; Modal's examples use scaledown windows of
    ~15 minutes, so effective cache lifetime is on the order of minutes, not
    hours. No guaranteed TTL is published.
  - Prefix match must start at token 0; any early-token change invalidates the
    rest of the prefix.
  - No minimum-token threshold is documented for Shared Endpoints (vLLM APC
    has no per-request minimum; benefit scales with shared-prefix length).

Pricing
  No separate cache-read/cache-write pricing is published for Modal Shared
  Endpoints; cache hits manifest as lower latency (TTFT) and fewer recomputed
  prefill tokens rather than a discounted token rate. Shared Endpoints bill
  per token; Dedicated Endpoints bill per GPU-second.
  See https://modal.com/pricing.

Maxing recipe
  1. Keep system prompt, tool definitions, and reference docs byte-identical
     at the head of messages; push all dynamic content to the tail.
  2. Send requests in quick succession so the same warm replica serves them
     (avoid scaledown gaps between turns).
  3. Avoid multi-tenant dilution you cannot control; accept that cold starts
     lose the cache and warm up with one "primer" request after idle periods.

Local-router integration
  local-router treats modal as an OpenAI-compatible endpoint:
  `prompt_cache_retention: '24h'` and a `prompt_cache_key` are injected for
  OpenAI-family models (harmless if ignored by vLLM), and a `prompt_cache_key`
  is set for kimi/moonshot-family IDs. No Anthropic-style cache_control
  blocks are injected for this provider since the upstream has no explicit
  caching API.
