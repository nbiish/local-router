nebius-us-north1 (Nebius Token Factory, us-north1 region) — Prompt Caching
Last verified: 2026-11-20

Overview
  Nebius Token Factory exposes region-pinned gateways on the same service as
  the global host:
  https://api.tokenfactory.us-north1.nebius.com/v1

  The region is a routing/residency boundary — same engine, same
  OpenAI-compatible surface, same credential. It exists so a workload that
  must be processed in a specific geography can name that geography in the
  route instead of hoping capacity lands there. Nebius documents that public
  serverless endpoints may run wherever capacity exists; only a pinned
  endpoint guarantees location. This provider row is that pin for the
  `us-north1` gateway.

Why this is a separate provider row and not a query parameter
  local-router's unit of key resolution, curation, policy, and fallback
  identity is the provider row. Two rows over one credential
  (NEBIUS_API_KEY, shared with the global `nebius` row) give region pinning
  for free: a route referencing `nebius-us-north1/...` cannot silently fail
  over to another region under the same name.

Mechanism
  Identical to the global host: automatic prefix/context caching with
  OpenAI-style reporting (prompt_tokens_details.cached_tokens), no
  cache_control API, no explicit breakpoints. See docs/caching/nebius.txt
  for the full mechanism, limits, and pricing, which this region inherits
  unchanged.

Reasoning dialect
  Measured on this host, matching the global host: `enable_thinking` is inert
  (on GLM-5.3-Flash it produced a byte-identical completion to the baseline),
  `reasoning_effort` moves billed reasoning_tokens, and the full six-value enum
  including `xhigh` is accepted. Advertised as EFFORT_SIX with
  acceptsXhigh: true and providerDeclaresDialect: true in
  src/provider-policy.ts — see docs/caching/nebius.txt for the per-family
  numbers.

Local-router integration
  Same injection as every Nebius row: a stable prompt_cache_key (sticky) and
  OpenAI 24h retention fields, which the chat surface ignores harmlessly and
  the Responses surface honours. Because the policy row is separate, a future
  divergence (a region gaining a knob the global host lacks) can be recorded
  without mis-describing the other gateway.
