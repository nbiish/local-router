## Threat Model

- **Assets protected:** Running `local-router` application identity binding, paid tier entitlements (Free / Pro / Business), remote HTTPS bridge access, and customer privacy (zero passwords stored or managed).
- **Adversaries:** Users copying a paired `account-lease.json` onto another machine to bypass the per-account device cap; local tampering with `account-lease.json` to forge `pro`/`business` tiers or extend expiry; expired/revoked remote bridge clients attempting continued remote inference access.
- **Worst realistic outcome if wrong:** Forged or transplanted leases passing verification; broken local loopback OSS workflows for unpaired developers; raw secrets leaking into `account-lease.json` or logs.

## Decisions Confirmed by Operator

1. **Tier-gated enforcement:** Local loopback routing (`127.0.0.1` / `localhost` / `::1`) stays usable with zero friction. Remote HTTPS bridge (`src/inbound-auth.ts`) and paired cloud/tier features enforce the PQC-bound ML-DSA-65 lease (fail-closed when a paired lease is expired/tampered/mismatched or when `LOCAL_ROUTER_REQUIRE_LEASE=1`).
2. **Federated OAuth identity via `local-router.com` (Google / Apple / Microsoft):** Running apps never ask for or store user passwords. They pair using a short-lived single-use pairing code issued after Google/Apple/Microsoft login on `local-router.com`, binding the user's verified email hash to this machine's local ML-KEM-768 public key (`recipient.pub`).

## Design & Files

- `package.json` — add `@noble/post-quantum` (`^0.5.4`) for FIPS 203/204 (`ml-kem-768` + `ml-dsa-65`) verification matching `local-router-dot-com` byte-for-byte across Node 22/24 on macOS, Windows, and Linux.
- `src/pqc-entitlement.ts` — new module implementing:
  - Alias-proof `normalizeEmail`, `computeEmailHash` (`SHA3-256`), `computeDevicePubHash` (`SHA3-256` over 1184-byte ML-KEM-768 public key), `computePqcBindingHash` (`pqc3:<sha3-256>`), `canonicalLeaseMessage`.
  - Local ML-KEM-768 identity loader/generator (`recipient.pub` in `pqc-secrets` dir, or app-managed ML-KEM-768 keypair fallback in `~/.config/local-router/device-pqc.json` mode `0600` when no `pqc-secrets` bundle is initialized yet — never plaintext credentials, strictly PQC device identity!).
  - ML-DSA-65 signature verification + binding-hash + device-key + email-hash + expiry validation (fail-closed on any mismatch).
  - Persistent lease store at `~/.config/local-router/account-lease.json` (`0600`, contains only signed public lease + verification metadata; wrapped renew token unwrapped into `pqc-secrets` or memory).
  - Pairing client (`pairWithControlPlane`) and lease renewal client (`refreshLeaseFromControlPlane`) targeting `LOCAL_ROUTER_CONTROL_PLANE_URL` (default `https://local-router.com`).
- `src/inbound-auth.ts` — integrate tier-gated lease check into `evaluateInboundAccess`:
  - Loopback remains ungated.
  - Public inference routes keep existing `LOCAL_ROUTER_ACCESS_KEY` verification AND enforce PQC lease validity when `LOCAL_ROUTER_REQUIRE_LEASE=1` OR when a paired lease is present on disk and invalid/expired/mismatched/lacks `remoteBridge` entitlement (`403` fail-closed).
- `src/index.ts` — wire loopback-only account pairing endpoints:
  - `GET /api/account/status`
  - `POST /api/account/pair`
  - `POST /api/account/refresh`
  - `DELETE /api/account/pair`
- `bin/localrouter.js` — add `localrouter account <status|pair|refresh|unpair>` CLI commands.
- `tests/pqc-entitlement.test.mjs` — unit + integration tests covering:
  - Byte-identical `computePqcBindingHash` and `ML-DSA-65` sign/verify round-trip (valid, tampered tier, wrong machine ML-KEM key, wrong email, expired lease).
  - End-to-end pairing with a mocked local-router.com control plane (ML-KEM-768 wrapped secret unwrap + ML-DSA-65 lease verification + disk persistence).
  - Tier-gated `evaluateInboundAccess` enforcement (loopback always allowed, remote bridge allowed with valid lease, blocked `403` on expired/tampered lease or when `LOCAL_ROUTER_REQUIRE_LEASE=1` and unpaired).
