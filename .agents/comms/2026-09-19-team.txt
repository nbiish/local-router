## update — fix/curation-single-provider-deselect
- start: 2026-09-19T22:05:00Z
- agent: orchestrator
- findings:
  1. Symptom reproduced and root-caused: `PUT /api/model-curation` is gated by `evaluateCurationShrink` (>=90% shrink of a >=10-key catalog => block). Deselecting OpenRouter (447 curated models of 466 total) is a 95.9% shrink, so the write returned HTTP 409, was never persisted, and the next page load re-fetched the old server-side selection — the "models keep coming back" report.
  2. Verified empirically: with the single-provider exemption disabled, a 20-of-22 single-provider clear returns 409 instead of 200 (test failure reproduced).
  3. Live config corroborated the scale: `~/.config/local-router/curation-backups/curation-full-2026-09-19T21-58-19-925Z.json` holds 466 keys with 447 openrouter, reason `PUT /api/model-curation (forced)`; the 21:51 snapshot holds 226 keys with 203 zenmux (ratio 0.889 — just under the 0.9 block threshold, so it snapshotted but did not block).
  4. Secondary defect: `refreshProviderEndpointModels({preserveCuration:true})` auto-curated newly discovered models unconditionally, undoing a deliberate full-provider deselect on the next automated refresh.
  5. UI had no recovery path for 409 on the debounced autosave path — the failure was silent (silent:true), so the selection reverted with no visible cause.
- fix:
  - `evaluateCurationShrink`: exempt targeted single-provider edits (providersBefore.size > 1 && removedProviders.size === 1 && remainingProviders.size >= 1) from the block. Whole-catalog wipes still blocked.
  - `refreshProviderEndpointModels`: gate new-discovery auto-curation on the provider having curated keys before the refresh.
  - `layout.ts`: provider "Deselect all" autosaves with `force: true`; 409 responses render an inline "Force Save" button and, on non-silent saves, a confirm() prompt.
  - Safety net retained: `guardCurationReplacement` still snapshots whenever a write removes >= half the catalog.
- verification:
  - `npm run build` clean.
  - New `tests/curation-merge-guard.integration.test.mjs`: single-provider clear 200, whole-catalog wipe 409, forced wipe 200 — passes.
  - Registered the new test in `package.json` `test:integration` (it was untracked and unregistered in the inherited WIP).
  - Full suite `npm run test:integration`: 150/150 pass, 0 fail.
