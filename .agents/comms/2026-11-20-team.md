# AGENT COMMS — 2026-11-20

<PROTOCOL>
## PROTOCOL (binding — follow like AGENTS.md)

**When:** ≥1 agent or subagent is working at once (multiple branches, features, updates, bugs, docs). Solo? Still check in/out — the ledger is the audit trail.

**Two channels:**
- **This file** (`.agents/comms/{date}-team.md`) — one file per UTC date; committed, append-only durable ledger. Never rotate per session or per hour. Updated via your task-branch commits; reaches everyone at merge.
- **Live board** (`.agents/comms/{date}-team.live.txt`) — gitignored, at the **main repo path**. Append here by absolute path for immediate in-flight visibility. Never `git commit` it; never `git add` it. Main stays clean.

**Read:** this file + the live board — at start, before any merge, and whenever blocked.

**Write:** for every lifecycle event, append one entry block to **both** the live board (immediate) and this file in your worktree (durable — commit it). One writer per branch. Subagents do not write the shared files directly: report results to your orchestrator, who logs on your behalf with `parent:` set.

**Skill distribution (persisted per-repo selection):** which `.agents/skills/` packs distribute to this repo is governed by the operator's persisted selection (`~/.config/ainish-coder/skills-selection.json`). `ainish-coder --rules` asks on a real terminal the FIRST time a repo has no saved selection, then applies that saved choice on every later run; `ainish-coder --select-skills [DIR]` reopens the choice and `ainish-coder --skills-list [DIR] [--json]` shows it. Agents and CI MUST use the headless path — `ainish-coder --rules <dir> --headless` or `ainish-coder --skills-sync <dir> --headless` — which applies the saved selection with no prompts. Do not hand-edit the selection file; run the interactive toggle instead. Scroll-channel packs (`8thfire-scrolls`, `ghost-layer-injector`, raw `.scrolls*/` payload) are never selectable here — explicit `--scrolls` only.

**Timestamps — mandatory, bracketed, ISO-8601 (UTC `Z` form on this ledger):**
- `start:` the instant the agent **begins** the action (input received / work begun).
- `end:` the instant the agent **finishes** it (output produced / work handed off or halted).
- **Every** entry has both. Abandoned mid-action → still close with `end:` + `status: abandoned`.

\*\*Entry block:\*\*

~~~
### [<ISO-8601 timestamp>] <EVENT> | branch:<branch> | wt:<worktree-path>
- start:<ISO-8601>               # input received / work began
- end:<ISO-8601>                 # output produced / work ended
- parent:<orchestrator>          # subagents only
- scope:<paths/modules>
- provenance:<source_commit=XXXXXXXXXXXX manifest_sha256=XXXXXXXXXXXX>   # optional but recommended
- objective:<one line>
- input:<one line — what was received or requested>
- output:<one line — what was produced or handed off>
- status:<new|in-progress|blocked|verifying|merged|abandoned>
- blockers:<none | description>
~~~

**Provenance stamp (recommended on `checkin`):** embed the ainish-coder root commit SHA and the target's deployment-manifest digest so every work session is auditable against the exact ruleset it ran under. Generate it with `ainish-coder --rules-provenance <dir>`, which emits `source_commit=… manifest_sha256=…`. Verify every target's manifest signature with `ainish-coder --rules-verify [--json]`.
