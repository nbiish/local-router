## Objective

Implement the top master suggestions from the 2026-10-31 review: the shared PQC
bundle must be observed, not assumed, and a local backend's credential must
never leave loopback.

## Change

- `src/local-backends.ts` — pure `isLoopbackEndpointUrl` / `localBackendKeyEgressAllowed`.
- `src/index.ts`
  - `PqcBundleDrift` + `checkPqcBundleDrift()`: stat-based fingerprint, one
    read-only resync on change, reports `added` / `removed` / provider counts.
    Called from `pqcStatusReport()` and the 15-minute health sweep (warning when
    providers disappear). Never writes the store, never drops in-memory keys.
  - `syncKeysFromPqcBundle()` records the post-sync baseline (`rememberPqcSyncState`).
  - Local-backend egress guard in the provider header builder and the model
    probe: a standard backend (llama.cpp, Unsloth) pointed off-loopback is
    refused before any request; cascade is suppressed for that configuration
    error so the operator sees the reason.
- Docs: PRD bullets for egress + drift; `docs/decisions.md` receipt-as-egress-record.

## Risks

  silent revocation); the warning + `bundleDrift` record make it explicit, and
  a restart or `/api/pqc/resync` reconciles.

  the intended incompatibility, documented in the PRD.
