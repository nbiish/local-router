# Fallback topology: cost-first ordering and the reasoning-dial gate

## Objective

Make the fallback chain use every configured provider the best way it can: an
ordering that reflects real cost, a chain that cannot silently degrade a request's
reasoning level, and no dead steps.

## What was measured before the change (2026-11-09, live router)

| Finding | Evidence |
|---|---|
| Ordering was fiction | `normalizeRoutingTierOrder` logged "Reordered fallback route by provider tier" while only de-duplicating. Nothing compared tiers. |
| Eligibility ignored capability | `filterEligibleFallbackModels` checked context and vision; `supportsReasoning` was declared in its spec type and never read. |
| The default seed was mostly dead | 23 of 25 ids in the hand-written seed, and 47 of 54 across the three presets, were absent from the live catalog. Dead steps cascade silently, so a long chain was mostly illusion. |
| Coverage had holes | 15 providers configured; `antigravity` (a whole OAuth subscription) had zero steps, `ollama` had zero, and one chain step (`nebius`) had no key. |
| A whole class of tiers was mispriced | Every `antigravity` row carries `tier:'paid'` because that is how Google labels the upstream model — yet the router reaches it through an OAuth subscription that is already paid for. |

## What was built

1. **`src/fallback-topology.ts`** — cost bands (`free` → `subscription` → `paid` →
   `unknown`, unknown LAST), capability ordering inside a band (context, then
   reasoning depth, vision, caching), stable so an operator's hand-order survives
   where no fact contradicts it. Ordering only reorders; it never drops a step.
2. **Access path outranks the tier label.** OAuth and loopback backends are
   already-paid capacity, so an `antigravity` model labelled `paid` sorts as
   subscription rather than behind metered billing.
3. **The reasoning-dial gate.** A request that expresses a thinking intent (any
   level, including `off`) requires a step with a real dial. A chain with none
   returns 400 with a reason instead of answering 200 at the model's own fixed
   depth. The largest-context rescue path operates on the already-narrowed set.
4. **Empty completions fail over.** A 200 with `finish_reason:'length'`, 900
   billed reasoning tokens and `content:''` used to classify as `generated`, so
   the chain accepted an empty answer. It is now `instant_error`. Tool-call-only
   turns and reasoning-only text are handled deliberately differently (see below).
5. **Seed rebuilt from facts.** `routing-defaults.ts` is band-structured and
   generated by `scripts/seed-fallback-chain.mjs`, which fails if a configured
   chat provider has no step. Presets derive from the same ids.
6. **`/api/routing/coverage`** reports absent providers, unkeyed steps, and
   single-step providers. Read-only: a diagnostic that mutates what it reports is
   not a diagnostic.

## Applied to production

The live chain was replaced with the generated 20-step chain covering all 14
chat-capable providers (backups at `~/.config/local-router/*.bak-20260909T0957*`).
**`router-settings.json` is the authoritative override**: it re-applies on boot and
overwrites `fallback-models.json`, so a write to the latter alone is silently
reverted — which happened on the first attempt and had to be redone on both files.

## Known remaining gaps (reported, not hidden)

- 8 providers are reached by a single step, so one failure loses the provider.
  The generated seed picks the most capable model per provider per band; adding a
  second step per provider would cost quota and is an operator decision.
- `commandcode`, `kilo` and `openrouter` steps land in `unknown` because their
  registry rows carry no tier fact. They sort last, which is the safe direction,
  but the facts would be worth filling in.
- `nous-portal-longcat-2.5-free`, `cursor-claude-opus-5-5-high`,
  `github-copilot-auto`, `kilo-openrouter-auto-code-paid` and
  `commandcode-crouton-alpha` have no reasoning dial, so they are excluded
  whenever a request names a level. That is correct behaviour, and it is why the
  free band's first step is skipped for reasoning requests.

## Incident during verification

A verification run on the shared `HOME` rewrote the operator's
`fallback-models.json`. It was restored from an explicit backup, and every later
verification used an isolated `HOME` so it cannot recur. Recorded here rather
than omitted: a verification harness that can mutate production config is a real
hazard, and the fix is procedural.
