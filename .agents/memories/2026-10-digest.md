## Insights

Loopback is the contract: never expose the router on all interfaces and never portproxy 0.0.0.0 to it; a stale WSL IP in a Windows portproxy silently redirects traffic to nothing. WSL's mirrored localhost means the 11434 contract server can live inside WSL — `wsl ss -ltnp` settles "already running" disputes after a Windows restart (2026-10-27-memory.txt, 2026-10-29-memory.txt).

The store that answers is the store the owning environment holds, not the one you think is running: a Windows instance answered 11434 with an empty store (23 curated / 2,006 cache / 0 keys) while the real store sat in WSL (73 / 2,706 / 20-step chain). Run --rules from the environment that owns ~/.config/ainish-coder (WSL side here: /mnt/d/Code/ainish-coder --rules /mnt/d/Code/local-router --headless); a Windows-side deploy flips the manifest source to /d and floods unselected packs (2026-10-29-memory.txt).

PowerShell: $home and $pid are read-only automatic variables — assigning them fails and the stale value silently retargets the command (use $smokeHome/$procId). Smoke isolation on Windows needs USERPROFILE (Node os.homedir honors it) and LOCAL_ROUTER_SKIP_OS_ENV=1 so the registry stays untouched (2026-10-28-memory.txt).

Windows process/FS traps: cannot spawn a .cmd without a shell, and shell:true joins argv with spaces — resolve wrappers to real .js/.exe; cannot enumerate the bare \\wsl.localhost root — run `wsl.exe -l -q` (UTF-16LE output) first; WSL appends the Windows PATH so /mnt/<drive> launchers must be skipped in CLI detection (2026-10-28-memory.txt, 2026-10-29-memory.txt). POSIX shim wrappers must follow symlinks before locating lib/*-runner.js (2026-10-28-memory.txt).

pqc-secrets export lines are shell-quoted (`export NAME='value'`) and pack refuses them — any persistence layer must strip the quoting or saves fail silently (2026-10-29-memory.txt).

Tests: providerEnvKeyValue reads only the namespaced env name (LOCAL_ROUTER_OPENROUTER_API_KEY), never the bare OPENROUTER_API_KEY (2026-10-30-memory.txt). Never run the verifier via spawnSync inside a test that hosts the fake upstreams — it blocks the event loop and everything times out; use async spawn. ainish-rag writes progress lines to stdout before its JSON, so the verifier extracts the JSON suffix (2026-10-31-memory.txt).

Model limits must be curated: provider /models and token-plan endpoints publish ids only or omit limits (zai, MiMo), so the numbers live in src/provider-model-registries.ts sourced from vendor docs/OpenRouter metadata — and curated rows must outrank cached defaults or a wrong default self-perpetuates across boots (2026-10-29-memory.txt).

Free-plan Ollama cloud: gemma4:31b-cloud works through the router as ollama/gemma4:31b-cloud even though /api/tags omits it; minimax:nemotron pulls return 402 on the free plan (2026-10-28-memory.txt). Codex reports "tokens used 0" against Ollama streams because upstream sends no usage — the router forwards none rather than inventing counts (2026-10-28-memory.txt).

A decision-model 400 must be excluded from the system-fallback cascade or it surfaces as a 502 from the empty system chain (2026-10-30-memory.txt). Audit receipts must be signed with the repo trust anchor, not a throwaway worktree key, or `audit verify` breaks later (2026-10-31-memory.txt). Repo-local PQC stores must never be created — use %TEMP% for test stores (2026-10-29-memory.txt).

## Recurring

Blocking sync child-process calls in HTTP-serving code: ollama pull via spawnSync blocked the event loop and launched the Windows app (2026-10-27-memory.txt), and the same spawnSync-inside-a-hosting-test pattern broke the verifier tests (2026-10-31-memory.txt). Rule: async spawn everywhere the process also serves requests or hosts upstreams.

The shared PQC bundle was rewritten out from under the router twice in two days: 2026-10-30 01:05 (PSIONICS_* rename; router boots keyless) and 2026-10-31 09:59:54 (LOCALROUTER_ keys gone, no backup). After each rewrite, provider keys must be re-entered via /config. Treat the shared bundle as untrusted, mutable input on every restart (2026-10-30-memory.txt, 2026-10-31-memory.txt).

The wrong process answering 11434: an all-interfaces listener plus stale portproxy (2026-10-27-memory.txt) and a Windows instance with an empty store while production lived in WSL (2026-10-29-memory.txt). Always verify which environment and which store the answering process owns before trusting a restart or an outage report.

Windows/WSL platform traps recur in every period record (read-only $home/$pid, .cmd spawning without a shell, \\wsl.localhost enumeration, Windows PATH appended in WSL, deploys from the wrong environment, checkout hooks flooding unselected packs from Git Bash). Platform shims need per-platform verification; Unix behavior cannot be inferred from Windows behavior or vice versa (2026-10-28-memory.txt, 2026-10-29-memory.txt).

Pre-existing baseline failures that are not regressions: custom-providers (second upstream prefetch / upstream request count 2 vs 1) and local-backends (port 8080 held by the llama.cpp embedding server) fail on main too — 157/159 is the clean baseline (2026-10-28-memory.txt, 2026-10-30-memory.txt adds antigravity-auth-platform-detect to that set); validate:model-specs 101 ERROR rows (2026-10-29-memory.txt) and the ainish-rag zero_trust red gate (2026-10-30-memory.txt) are likewise pre-existing.

Secrets and stores leaking into repos: .pqc-e2e/ (private.key.enc + bundle) left uncommitted in D:\Code\pqc-store-integration, cleaned up as e35c2f9 — test PQC stores belong in %TEMP%, never repo-local (2026-10-29-memory.txt).
