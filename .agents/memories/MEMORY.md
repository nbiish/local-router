## Decisions
- [2026-09-20] No-https-policy: tools refusing http://localhost base URLs are unsupported by policy; cross-boundary (Windows->WSL) access is a deployment concern solved by netsh portproxy or mirrored networking, NEVER a public tunnel (router has no inbound auth). *(source: operator directive 2026-09-19)*

- [2026-09-10] Graceful Cascade on Preflight Failures: Preflight failures (unknown model, no provider, no key/credits, allowlist reject) log skipped: true, stageAttempts: 0 and advance immediately to next fallback stage with zero retries; chain fails only on total exhaustion. *(source: memorix reasoning #5, engram obs:7)*

## Gotchas
- [2026-11-12] hermes resolves **named** `providers.<name>` config blocks before its documented `ollama→custom` alias: `model.provider: ollama` routed to the named `providers.ollama` block (the operator's real `ollama` process on 127.0.0.1:11435 with `:cloud` models), silently ignoring `model.base_url` and returning `HTTP 404: model 'local-router/fallback-models' not found` from the wrong server — the router never saw the request. Shim wiring must use the named `providers.local-router` block (`api: http://localhost:11434/v1`). Also `hermes config set model.provider <name>` clears `model.base_url`/`model.api_mode` on provider switch ("endpoint resolves automatically"). pi has no built-in Ollama provider — its `models.json` compatible-endpoint entry is the documented path. *(source: obs)*
- [2026-11-09] A verification harness that runs against the real `HOME` can rewrite production state: a scratch-port boot on the operator's home reordered `fallback-models.json`. Always give a verification run an isolated `HOME` and a scratch port, and back up before applying config. *(source: obs)*
- [2026-11-09] A 200 with `finish_reason:'length'` and empty `content` is a failed turn, not an answer: `openrouter-lfm-3-1.7b-free` with `reasoning_effort:'high'` billed 900 reasoning tokens and returned nothing while the fallback chain counted it a success. `classifyResponseContent` now treats no-content-no-tool-calls as `instant_error`; tool-call-only turns and reasoning-only text must still pass. *(source: obs)*
- [2026-11-08] A capability flag and the dial beneath it must be computed from the same facts. After the policy deploy the live router advertised 81 `reasoningEfforts` dials but only 40 `capabilities.reasoning:true` — a client reading the flag never renders the control, so the dial was unreachable. `/api/show`'s `capabilities` had the mirror bug (keyed off the dial, disagreeing with `/v1/models` for every cursor row). Both now answer "does this model reason" from one function. *(source: obs)*
- [2026-11-08] Only 3 of 1432 curated registry rows carry `supportsReasoning`, so a capability audit that trusts that flag will conclude most providers do not reason — including ones that do. Verify with a live call and billed `reasoning_tokens`, not with the stored boolean. *(source: obs)*
- [2026-11-08] A short prompt always reports `cached_tokens: 0` because it sits under every provider's minimum cacheable prefix (256 tokens Moonshot/Qwen, 1024 Anthropic/OpenAI). Any cache verification must use a prefix over that minimum or it proves nothing — `scripts/verify-live-cache.mjs` builds ~1300 tokens deliberately. *(source: obs)*
- [2026-11-08] Two wires silently dropped the caller's thinking level for months while every test stayed green: `/v1/messages` built its chat body from a fixed field list, and `translateResponsesRequestToChatBody` never read `body.reasoning`. The lesson is structural — a handler that assembles its own body bypasses the translator, so delivery has to be asserted at the route level, not only on the translation helpers. *(source: obs)*
- [2026-11-08] `injectPromptCaching` used to stamp breakpoints without counting the caller's own. Claude Code ships 4 markers and Anthropic caps at 4, so the extra markers earned a 400 instead of a cache hit. Any future marker injection must budget against the existing count. *(source: obs)*
- [2026-11-08] A policy row's `note` field is documentation, not evidence. `tests/provider-policy-docs.test.mjs` requires every caching row to cite an existing `docs/caching/*.txt` and every reasoning row to cite a measurement, a repo doc, a code path, or an explicit `[INFERENCE]` marker — so a claim without a source fails CI rather than reading as fact. *(source: obs)*

- [2026-11-10] Bulk settings writes must not follow `persistFallbackModels()` with a narrower `saveRouterSettings(payload)`: `persistFallbackModels` writes every route, and the second call replaced the file with `{ fallbackModelsText }` alone, dropping `fallback-embedding`/`fallback-decision` from disk on every `PUT`/`DELETE /api/router-settings`. - [2026-11-20] A failure classifier that reads the body before the status will eventually classify a successful answer as a failure. `AUTH_RE` carried a bare `auth` alternative, so HTTP-200 completions whose reasoning text said "the author of this request…" were booked `upstream_http_auth` — 45 live stages. Because `key_rejected` is a one-strike immediate quarantine, each one evicted a working provider. The classifier is now status-first and gates body regexes on `bodyIsCompletion`: a 2xx that parses as a completion is never auth/limit evidence, while a 2xx carrying an `error` payload is still classified from its body (some surfaces use 200 for real failures). *(source: obs)*
- [2026-11-20] The router was the cause of 11% of its own fallback failures. Six classes, all measured by replaying the live trajectory log: bare-`auth` regex (45), trailing `system` message from the failover marker rejected by Z.ai as code 1214 (21), unclamped `max_tokens` above the target's ceiling (30), `prompt_cache_key`/`store` sent to Google's strict schema (~40), `estimateRequestContext` folding the raw `max_tokens` into the context requirement (30 records), and hard-excluding no-dial models whenever a level was requested (167 of 200 requests). The first and last were the damaging ones: one poisoned the health registry, the other made two paid subscriptions unreachable. *(source: obs)*
- [2026-11-20] Excluding a capability is not the same as refusing to downgrade. A request that chose a thinking level excluded every model without a request dial, which kept the downgrade non-silent but produced a 400 instead of an answer — measured at 167 of 200 requests, with cursor-auto, github-copilot-auto and two cursor ids never reachable. The fix is a partition, not a filter: dial-capable members first, no-dial members as a `degraded` tier attempted only after every dial-capable one fails, and each tier-2 acceptance stamped `reasoningDialDowngraded` with the requested level. The downgrade is now recorded AND the capacity is kept. *(source: obs)*
- [2026-11-20] A trajectory log that records only the CLIENT's request cannot distinguish a provider fault from a router fault. Every defect in the 2026-11-20 audit was a property of the outbound body, and none was recoverable except by reading a truncated `providerErrorPreview` by hand. Schema 3 records `stages[i].outbound` as a content-addressed receipt on both success and failure paths. Corollary found live on the first v3 record: a receipt must be either fully inline or fully spilled — a 422-byte body was past the 400-char preview cap yet under a fixed 4 KB spill threshold, so it was neither and `readReceiptPayload` returned null. Spill when the preview truncates, not at a fixed size. *(source: obs)*
- [2026-11-20] Provider rows must state whether their wire validates its schema. Google's AI Studio OpenAI-compat surface rejects unknown field names outright (`Invalid JSON payload … Unknown name "prompt_cache_key"`), so a "harmless" cache-warming key fails the whole request — ~40 live failures. `CachingPolicy.requestFields.validation: 'strict'` now declares this, and `dropUnsupportedRequestFields` filters to the documented chat core for those rows while recording every dropped name. A lenient surface keeps byte-identical passthrough, so the gate costs nothing where it is not needed. *(source: obs)*
