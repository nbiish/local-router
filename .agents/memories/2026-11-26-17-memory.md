# Memory — 2026-11-26 17 UTC

- local-router release chain: a `v*` tag publishes the release and (after `fix/release-promotion-chain`) verifies the updater manifest, fast-forwards `production` and dispatches the website. A release created by the workflow's own `GITHUB_TOKEN` raises no `release` event, so promotion must be a `workflow_call`, not an event trigger. Manual fallback: `gh workflow run promote-website-release.yml -f tag=vX.Y.Z`.
- Desktop app IPC: the dashboard is served from `http://127.0.0.1:11434` — a remote origin for Tauri IPC. Any app command the dashboard calls needs BOTH `AppManifest::commands` in `src-tauri/build.rs` (which generates `allow-<command>`) AND a capability naming that permission with `remote.urls`. Without both, the button shows "Update check failed." while the page silently falls back to the git-based "Source up to date" text.
- The updater looks platforms up by exact `{os}-{arch}` (the crate never mentions `darwin-universal`); a release manifest must carry `darwin-aarch64`, `darwin-x86_64`, `windows-x86_64` and `linux-x86_64`.
- The running app's version is `CARGO_PKG_VERSION` (Cargo.toml), not a config override and not Info.plist; a version test needs the `Cargo.toml`/`Cargo.lock` entries changed too.
- minisign `ED` signatures (what the Tauri signer emits) verify as BLAKE2b-512 of the file plus a global signature over `signature || trusted comment`; the `.sig` file and the manifest `signature` field are base64 of that text.
